# Security 6.1: изолированные области vault (LAB)

Только синтетическая репетиция неизменяемого набора, без активного переключателя и без подключения к действующей IndexedDB.

- School: школьные таблицы и явно классифицированные записи.
- Coach: тренерские таблицы, включая незавершённые матчи, и явно классифицированные записи.
- Workspace: отдельный пароль владельца для полной meta, архивов (в архиве есть локальные настройки), упражнений, событий, инвентаря и турниров. Никакие общие записи не дублируются в школьном и тренерском контейнере. Классификация по типу не анализирует семантику свободного текста; не является разграничением прав реальных пользователей.
- Три независимых пароля, три отдельные базы LAB, криптографически аутентифицированный ID набора внутри каждого контейнера. Смешивание разных наборов, неправильный пароль, неизвестный тип, отсутствующая область и неверные связи при объединении отклоняются.
- Полная проверка связей и повторное открытие после записи; сверка всех таблиц по первичным ключам. Служебные sync-checkpoint записи не переносятся (отказ, не тихое удаление).

Между тремя БД нет атомарной транзакции. Если одна стадия прервана, частичный набор не открывается как полный; для новой репетиции использовать новые пустые LAB-базы. Не удалять источник. Модуль не защищает от отката всего набора, не предоставляет сквозные транзакции, ротацию набора, атомарную активацию, полноценное управление ключами и независимую production-авторизацию. Физические устройства и реальное содержание архивов не проверены.

Проверка: `node --test tests/vault-scope-bundle.test.mjs`; затем весь CI на точном SHA.


## Неизменяемая активация полного набора (LAB)

`vault-bundle-activation-lab.mjs` проверяет три независимых пароля, аутентифицированные ID и ревизии всех областей, а также равенство с явно переданным ожидаемым снимком. Только после этого одна транзакция отдельного registry сохраняет указатель. До неё scoped API не выдаёт данных. Отказ при записи указателя допускает повтор активации; неполный набор и повторная активация отклоняются. Каждое чтение сверяет аутентифицированную ревизию с закреплённой в указателе. Пароли не записываются. Web Locks сериализует кооперативные обращения к registry; при отсутствии API отказ.

Проверки имитируют квоту на второй области и на записи указателя, несовпадение исходного снимка, неверный пароль, повтор и подмену ревизии. Набор неизменяемый, без сквозных транзакций или маршрутизации действующей базы; источник передаётся вызывающей стороной и не блокируется этим модулем. Доступ по raw IndexedDB, полный откат профиля и независимая авторизация не покрываются. При неполной записи новый ID репетиции обязателен; существующие данные не удаляются.


## Сеансы чтения с неизвлекаемыми ключами (LAB)

`openVaultReadSessionLab` проверяет пароль и весь снимок, выводит неизвлекаемый CryptoKey, привязанный к salt и ревизии, и возвращает только интерфейс чтения. Пароль не хранится в объекте сеанса; каждое чтение заново аутентифицирует снимок без повторной PBKDF2. Блокировка вручную или по истечении тайм-аута (по умолчанию 5 минут) очищает ссылку на ключ и отменяет выдачу результатов незавершённых чтений; тайм-аут также проверяется по монотонным часам при обращениях. Ошибка чтения/смена ревизии закрывает сеанс. `openScopeSession` дополнительно сверяет активный registry при каждом чтении и позволяет независимо закрывать области. После перезапуска пароль нужен снова.

Это неизменяемое чтение LAB, не управление ключами действующего приложения. JavaScript не гарантирует физическое стирание памяти; уже выданные данные, ссылки вызывающей стороны и начавшиеся операции WebCrypto не могут быть отозваны. Привязка к lifecycle экрана, скрытию вкладки, синхронизации блокировки между вкладками, ротация и writable adapter остаются открытыми. Не использовать на рабочих данных. Тесты: expiry, блокировка незавершённого чтения, ошибочный пароль, другая база, устаревшая ревизия, независимые области и повторное открытие.


## Lifecycle экрана LAB

`vault-session-lifecycle-lab.mjs` закрывает все области при скрытии документа, freeze или pagehide; скрытый экран не может открыть сеанс. Отдельная блокировка не затрагивает другие области. Счётчик поколения отбрасывает результат незавершённой авторизации и чтения после блокировки или повторного входа. Два синтетических теста проверяют события и гонки; WebKit smoke использует настоящие IndexedDB и WebCrypto и программно генерирует pagehide. Это не физический тест сворачивания iOS. Нет UI production, общей блокировки других вкладок или удаления уже выданных данных из UI. После возврата требуется явный ввод пароля.


## Интерфейс синтетического стенда

При запущенном `npm start` открыть `http://127.0.0.1:8099/tools/prototypes/vault-ui/index.html`. Стенд доступен только на localhost в защищённом контексте с Web Locks. Кнопка создания использует исключительно синтетический снимок и три публичных демо-пароля, показанных на экране; настоящие пароли и рабочие данные не принимаются. Можно открыть области по отдельности, проверить число таблиц и записей, закрыть область, затем снова открыть после перезагрузки. При скрытии, freeze, pagehide и истечении сеанса показанные счётчики удаляются; пароль очищается при отправке. Новый демо-набор получает отдельный ID без удаления существующих БД. Никаких импортов рабочих резервных копий, сетевых запросов и доступа к живой БД. Это проверка UI read-only LAB, не пользовательская миграция и не production security. Браузерный smoke проверяет неверный демо-пароль, независимую блокировку, повторную авторизацию, mobile viewport и отказ при отсутствии Web Locks.


## Общая блокировка вкладок LAB

Явная кнопка «Заблокировать все вкладки» закрывает локальные области и отправляет через BroadcastChannel одного ID демо-набора только `{kind:'lock-all',version:1}`. Получатели закрывают сеансы и сбрасывают незавершённые чтения/открытия, очищают счётчики и поля пароля. Другой ID не затрагивается; локальная блокировка области и lifecycle не рассылают сообщения. Повреждённые сообщения не интерпретируются как команды; ошибка канала закрывает локальный доступ. При отсутствии BroadcastChannel UI не открывается. Нет подтверждения доставки, долговечного журнала или гарантии против атакующего с доступом к origin; при скрытии каждая вкладка блокируется самостоятельно. Это кооперативный синтетический стенд, не отзыв production-ключей. Тестируются гонка открытия, независимость ID, отсутствие данных в сообщении, отказ канала и настоящий межвкладочный WebKit при поддерживаемом API.

## Записываемые области с атомарным указателем (отдельный LAB)

`vault-partitioned-lab.mjs` — новая синтетическая репетиция, не переключатель действующей базы. Три независимо шифруемых области в отдельных object stores одной новой IndexedDB `teachapp-vault-mutable-lab-*` и отдельный registry. Первичная активация всех трёх ciphertext-снимков и указателя атомарна. Каждая последующая запись сравнивает все ранее аутентифицированные байты области, её ревизию и ID набора внутри одной native транзакции, сохраняет новые ciphertext и актуальный указатель вместе; обновления других областей не затираются. Отдельный неизвлекаемый PBKDF2-сеанс каждой области привязан к аутентифицированному bundle ID; пароль не сохраняется, соль, ID ревизии и IV обновляются при каждой записи. Чтение и запись ограничены таблицами и классификацией записей данной области, stale session отклоняется; close и тайм-аут отзывают доступ. Полное чтение требует все три пароля, один атомарный снимок ciphertext и полную проверку объединённых связей.

Синтетические тесты и WebKit покрывают одновременные записи, неправильный пароль, чужие таблицы и записи, устаревшую ревизию, закрытие до фиксации, симуляцию ошибки квоты на указателе и атомарный отказ при staging. Это полно-снимочный baseline с ограничениями: метаданные настроек остаются owner-only; школа не получает полный store с meta. Исторические связи, которые не проходят локальную проверку без архива (например, gradeHistory), не принимаются при stage. Уникальность ID и связи между областями дополнительно проверяются при полном объединении; сквозных транзакций, маршрутизации смешанных операций, production UI, миграции/удаления plaintext, измерения физической квоты, ротации/переноса набора и независимого аудита пока нет. Не использовать рабочие данные. Указатель и ciphertext могут быть совместно откатаны атакующим с доступом к профилю; это не защита от произвольного JS внутри origin.
