# Публичная страница TeachApp — настройка Firebase

Портал не требует собственного сервера. GitHub Pages обслуживает HTML/CSS/JS, Firebase Realtime Database — только выбранную для публикации проекцию. Публикация выключена по умолчанию. Один аккаунт тренера и одна постоянная ссылка на команду; одновременно редактируйте её с одного устройства. При удалении команды или сбросе локальных данных сначала снимите её публичную страницу с публикации: удаление локальной базы не удаляет внешние данные.

## Один раз в Firebase Console

1. Создайте проект на тарифе Spark, добавьте Web-приложение. Скопируйте Web API Key (не service account и не секрет базы).
2. В Authentication → Sign-in method включите Email/Password. В Authentication → Users создайте отдельного пользователя тренера с надёжным паролем. Скопируйте его UID. Не включайте анонимную запись.
3. В Realtime Database создайте базу в подходящем регионе в закрытом режиме. Скопируйте полный HTTPS-адрес базы. Для отдельного проекта портала откройте Rules, вставьте содержимое `firebase-portal.rules.json` из корня репозитория и нажмите Publish. Не заменяйте этими правилами существующую рабочую базу с другими данными.
4. В Data добавьте дочернее значение `publishers/<UID>` типа boolean со значением `true`. Это список разрешённых аккаунтов; изменение из браузера запрещено.
5. В TeachApp: Кабинет тренера → Матчи → Площадка и матч → Публичная страница команды. Укажите адрес RTDB, Web API Key, почту и пароль. Код страницы генерируется автоматически; если восстанавливаете страницу на другом устройстве, введите прежний код из параметра team в ссылке и используйте тот же аккаунт и базу. Сохраните ссылку отдельно.
6. Добавьте расписание и нажмите «Опубликовать страницу». Скопируйте постоянную ссылку. Без публикации Firebase не получает расписание и счёт.

## Во время матча

Автоматический старт работает для подробного матча при единственном совпадении даты (по устройству тренера) и соперника, если включена настройка. Иначе запустите публикацию вручную через управление матчем. Наступление планового времени само не создаёт LIVE. После записи каждого действия обновляется публичный снимок; если сеть недоступна, локальный матч продолжается. Повторные попытки выполняются, пока открыто приложение и сохранена авторизация. При повторном открытии матча авторизуйтесь в Firebase заново; пароль и токены не хранятся. Зрители видят последнее полученное состояние и предупреждение при отсутствии связи или свежих обновлений.

В бесплатном Spark есть лимит 100 одновременных подключений и ограничения трафика. Для небольших матчей этого обычно хватает; следите за Usage. Счёт, события и расписание — публичные. Номера игроков выключены по умолчанию; включайте только при необходимых разрешениях. Имена, контакты, здоровье, тактическая разведка, составы и приватные заметки не отправляются. Архив ограничен 20 матчами, лента — 30 событиями. Обратный отсчёт локальный.

## Проверка перед реальным использованием

- Откройте ссылку в приватном окне без учётной записи: расписание читается, запись запрещена.
- Попробуйте запись с другим Firebase-аккаунтом: отказ. Проверьте отказ записи неизвестного поля и корневого чтения.
- Запустите тестовый матч, проверьте счёт, отмену, смену партии, отключение сети и восстановление.
- Снимите страницу с публикации, дождитесь подтверждения. Публичная ссылка должна показывать отсутствие данных. Удаление на сервере не отзывает уже скачанные копии.
- Удалите тестовые данные. Не публикуйте реальные имена учащихся или чувствительную информацию.

Проверка правил на синтетических аккаунтах (Java 21+):
```sh
npx -y firebase-tools@latest emulators:exec --only auth,database --project demo-teachapp "node tools/firebase-portal-emulator.mjs"
```

Эмуляторы слушают loopback. Проверяются вход, разрешение владельца, отказ записи для зрителя и второго аккаунта, запрет просмотра списка страниц, проверка полей и снятие страницы с публикации.
