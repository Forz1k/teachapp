# Карта TeachApp

`index.html` подключает локальный SheetJS, стили и модуль `js/app.js`. Приложение загружает состояние через `store.load()`, выбирает экран и подписывается на изменения. Экраны в `js/screens/` обслуживают журнал, быстрый ввод на уроке, классы, участие, освобождения, расписание, КТП и настройки. Общие шторки, подтверждения и скачивание файлов находятся в `ui.js`, оформление для iPhone — в `css/app.css`.

`model.js` содержит вычисления без DOM и IndexedDB: локальные календарные даты, интервалы, оценки, освобождения, расчёт расписания с заменами. `store.js` связывает модель и базу, хранит массивы в памяти и вызывает подписчиков после изменений. `export.js` строит матрицы из состояния, читает и записывает таблицы, вызывает методы хранилища при импорте.

## Локальные данные

База teachapp, версия схемы 4. Первичный ключ всех записей — id. Классы и ученики связаны через classId. Уроки индексируются по классу и дате. У оценки уникальна пара lessonId/studentId, у месячной записи — studentId/year/month. Освобождения индексируются по ученику и дате начала. КТП содержит classIds, темы — ktpId и ktpOrder. Недельный шаблон schedule использует weekday/slot, правки scheduleOverrides привязаны к дате. Настройки находятся в meta. Хранилище participation индексируется по ученику, уроку и дате, пара studentId/lessonId уникальна. Запись режима и изменение связанного ОСВ выполняются одной транзакцией. Старое monthly остаётся в резервных копиях.

Для изменения схемы повысить DB_VERSION и добавить последовательный обработчик в migrations в db.js. Все шаги выполняются в транзакции обновления IndexedDB. Резервная копия формата 2 содержит объект data по именам всех хранилищ. js/backup.js также распознаёт формат 1. db.dumpAll читает согласованный снимок, db.replaceAll заменяет все хранилища в одной транзакции после проверки. Версии формата, схемы и приложения независимы.

## Запуск и выпуск

Node.js 24, npm ci. Запуск через npm start (Python, localhost:8099). Для тестирования отдельного файла использовать node --test tests/имя.test.mjs, перед выпуском — npm test и npm run validate. CI повторяет проверки при push и pull request.

Источник версии — package.json. Добавить раздел версии в CHANGELOG.md и выполнить npm run release -- X.Y.Z. Команда обновляет lock-файл, модуль интерфейса и константу SW. При добавлении клиентского модуля включить его в PRECACHE. Пути относительны для размещения в подпапке. Сервер и внешние CDN для работы приложения не требуются.

## Точки риска для следующих этапов

Экспорт месячных строк и фильтр периода относятся к этапу 2. Каскады освобождений — к этапу 5. SW использует атомарный addAll и кеш с привязкой к области регистрации. Готовое обновление ждёт подтверждения. Каникулы хранятся в meta.settings.holidays. Планировщик создаёт один урок класса на дату, в сводке КТП один урок считается одним учебным часом. Подписка приложения перерисовывает экран после изменения состояния (этап 8).

## Проверка нагрузки

В js/health.js находятся каталог с несколькими родителями и чистая проверка совпадений. Пользовательские категории хранятся в activityCategories, профили — в studentHealthProfiles по ID ученика, ограничения — в activityRestrictions. Темы содержат подтверждённые activityIds. У урока null или отсутствие поля означает наследование, пустой массив требует проверки. Группа не участвует в сопоставлении. Выбранное упражнение и вариант участия сохраняются в participation.


## Дневной обзор и обновление журнала

`js/screens/today.js` строит дневной обзор из расписания, журнала и проверок нагрузки. Просмотр не создаёт урок. `store.notify(studentId)` группирует ручные изменения отметок; подписчик получает список учеников либо null при структурной правке. `renderJournal` возвращает функцию точечного обновления строк, а app.js сохраняет прокрутку при полной отрисовке того же маршрута.


## Учебные периоды и нормативы (1.8.0)

Периоды хранятся в settings.trimesters для совместимости; kind и name определяют вид. Шкалы и результаты находятся в norms/normResults (схема 5, копия 3). Результат содержит снимок шкалы, перенос оценки требует подтверждения и пустой ячейки. Ограничения переиспользуются, не являются медицинским допуском. Посещаемость считается по подтверждённым клеткам проведённых уроков.


## Волейбольный режим (1.9.0)

coach.js работает только с coachTeams, coachPlayers, coachTrainings и coachMatches. Связей со школьными идентификаторами нет; статический справочник нагрузок общий, сведения об ограничениях вводятся отдельно. Составы событий сохраняются, архив игроков не уничтожает историю. Запись проверяется в транзакции, резервная копия 4 охватывает обе области и валидирует связи. CSV не включает ограничения. Режим отделяет интерфейсы, но не является аутентификацией или отдельным зашифрованным хранилищем: полный JSON содержит обе области. Пустая статистика не превращается в ноль; посещаемость считается по отмеченным проведённым тренировкам.


## Финальный релиз 2.0.0

finalGrades содержит исторический диапазон периода и оценку, подтверждённую преподавателем. Не меняет уроки. Шифрование файла: AES-256-GCM, PBKDF2 SHA-256 600000 итераций, случайные соль 16 байт и IV 12 байт, проверка целостности. Пароль не сохраняется; IndexedDB не зашифрована. Полная копия включает обе области; обычные CSV и печать — только выбранный минимальный отчёт. Экранная ширма не является контролем доступа. Очистка сроков удаляет только истёкшие записи групп и ограничений после подтверждения, не меняет справки, оценки или историю участия. Схема 7, резервная копия 5 с чтением 1–4.
