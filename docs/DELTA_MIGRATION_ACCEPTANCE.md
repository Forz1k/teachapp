# Delta LAB — чек-лист перехода (не production)
 
**Текущий рабочий протокол TeachApp 5.1.1 не меняется.** Это техническая репетиция переноса, а не инструкция для самостоятельного изменения рабочих адресов.
 
## До копирования
- [ ] Отдельные локальные серверы, синтетические записи, разные ключи и пароли.
- [ ] Проверена полная защищённая копия каждого исходного устройства; сохранены пароли и текущий исходный адрес.
- [ ] Все устройства синхронизированы; inspectDeltaMigrationDevice показывает clean-source для каждой действующей копии. Не считать fresh-device готовым к переносу.
- [ ] Нет черновиков LIVE в контуре тренера. Согласованы удаления и конфликты.
- [ ] В дальнейшем production потребуется настоящая серверная блокировка старых записей с подтверждением устройств; в LAB это только явное ручное подтверждение.
 
## Репетиция
- [ ] prepareDeltaMigration: источник читается, целевой контур пуст, в файл записаны два зашифрованных снимка.
- [ ] Сохранить файл отдельно, открыть через openDeltaMigration, проверить контур, ревизию, workspace ID, digest и совпадение содержимого.
- [ ] commitDeltaMigration только после подтверждения. Проверить verified-copy, а не source-changed, independently read/verify destination. Новый workspace ID, ревизия 1, старый сервер неизменен.
- [ ] Повтор операции не создаёт новую ревизию. Попытка другого снимка в непустой контур запрещена.
- [ ] Проверить прерывание, перезапуск, устройство с локальными изменениями, позднюю запись источника, изоляцию контуров, восстановление файлов.
 
## Блокеры рабочего перехода
- [ ] Production изоляция, серверный барьер записи, долговременная авторизация и защита от злоупотреблений.
- [ ] Безопасная привязка проверенной локальной базы к новой последовательности, совместимость старых версий, атомарное переключение профиля и контрольных точек на каждом устройстве.
- [ ] Реальные ПК и iPhone: офлайн, переподключение, резервирование, отзыв ключей и откат.
- [ ] Решение об отключении старого сервера только после независимой приёмки. Не удалять его данные автоматически.
 
При source-changed не переключать устройства: целевая копия может быть устаревшей. Не очищать IndexedDB и не заменять локальные данные резервной копией вслепую.
