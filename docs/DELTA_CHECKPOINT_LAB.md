# Delta 6.2 — проверка протокола и независимое восстановление LAB

Только синтетические данные и локальные тестовые серверы. Не изменяет production Worker, обычные профили TAP1/TAD2, IndexedDB или режим автообмена.

## Строгий транспортный контракт

Клиент `deltaLabClient` проверяет полный состав head (включая лимиты и эпоху ключа), тип и номер ревизии, структуру ответа на запись, multipart begin/part/commit, барьер назначения. Лишние/отсутствующие поля и несовпадение ревизии отклоняются. Неопределённый результат записи не считается подтверждением; существующая логика синхронизации требует повторной сверки. Для аутентифицированного Delta-пакета более новой backupVersion введён отдельный код newer-backup-format. Проверка формата не заменяет расшифровку и аутентификацию содержимого. Подписанная квитанция rollback проверяется существующим серверным протоколом.

## Независимая копия

- `exportDeltaCheckpointLab`: читает полный аутентифицированный префикс, требует точные area/workspaceId/revision и отдельный пароль резервной копии. Сохраняет только зашифрованный снимок, идентификаторы источника и digest. Не сохраняет ключ доступа, пароль обмена или административные секреты. Повторно открывает результат для проверки. Историческая ревизия не равнозначна замороженному серверу.
- `openDeltaCheckpointLab`: полностью офлайн, проверяет формат, область, ожидаемые идентификаторы, версию, digest и связи со схемой; возвращает данные для предпросмотра, ничего не записывает.
- `prepareDeltaCheckpointRestoreLab`: офлайн готовит точный шифротекст нового якоря на ревизии 1, с новым workspaceId, другим локальным сервером и независимым паролем. Сохранить план вместе с исходной копией до записи.
- `restoreDeltaCheckpointLab`: требует явного подтверждения проверки файла и ID назначения. Допускает пустой сервер либо точное повторение того же якоря, затем проверяет фактический снимок. Запрещает перезапись другой истории, закрытый контур и автоматический cutover. Потеря ACK требует повторного запуска с тем же планом, а не генерации нового. При изменении назначения остановиться и провести диагностику.

Тесты проверяют битый/чужой ответ, новую версию, разрыв цепочки, независимую копию, неправильный пароль, подмену digest, потерю ACK и запрет перезаписи. Расширенный Delta smoke восстанавливает копию при выключенном источнике в отдельном локальном workerd и проверяет результат после рестарта. Ни одна операция не переключает рабочие устройства. Production-конфигурация, внешняя авторизация, физическая приёмка, масштабирование и эксплуатационный план миграции/отката всё ещё требуют отдельной проверки.
