# Push subscription lifecycle LAB

A synthetic injected adapter models getSubscription/subscribe/unsubscribe and standard PushSubscription properties. Only example.invalid endpoints and expected key lengths are accepted. The caller supplies explicit current UI consent, existing permission and VAPID public key; no requestPermission is performed, no default PushManager is used. Existing subscriptions are not automatically replaced on VAPID rotation or expiry. Commands serialize per controller and recheck context after awaits. An uncertain late creation/removal requires reconciliation rather than blind cleanup. Revocation is allowed even with denied permission. Public results contain state only, no endpoint, auth or key. Tests cover explicit consent, rotation, expiry, invalid endpoint, unknown result and concurrent commands. This is a mocked adapter, not real browser subscription registration or server binding; no cross-tab atomicity, real key persistence or provider acceptance.
