# End-to-end synthetic Web Push cycle

The integration test connects the actual LAB subscription/inbox policy, encrypted transport, an independent in-memory receiving fixture (pinned VAPID key and origin/expiry verification, RFC 8188 header parsing and independent ECDH/HKDF/AES-GCM decryption), and the generic receiver handler. The transport is injected: it never uses fetch or a real push endpoint. Tests demonstrate that accepted transport does not acknowledge the inbox, an explicit acknowledgement cancels further attempts for that sequence, a different recipient is not queued, wrong signing key and corrupted ciphertext are rejected, and a revoked/stale subscription cannot display or initiate the rehearsed signal. The local consent predicate is a synthetic oracle, not a remote revocation guarantee; a real device may already have accepted a notification. Separate physical acceptance, external push provider, real subscription key storage, secure egress and server scheduling remain open.
