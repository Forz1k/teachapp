# Security 6.1 — модель угроз и контрольная точка

- Экранная блокировка защищает от случайного просмотра, не от доступа к профилю браузера/DevTools. Ошибка чтения настройки теперь не означает отсутствие блокировки. Устаревший верификатор не даёт открыть экран. Не объявлять эту меру шифрованием базы.
- Резервные копии: существующий AES-GCM + PBKDF2, пароль хранится отдельно. Проверить восстановление на отдельном профиле до миграции.
- Следующий этап: проектирование шифрования IndexedDB с аутентифицированными конвертами и уникальными IV, ключ только в памяти, независимые school/coach, работа без сети, индексы с минимальным раскрытием. Миграция в отдельное хранилище с проверкой полноты и обратимым переключением, не удалять исходник до независимой приёмки. Нужны тесты квоты, прерванной транзакции, неверного пароля, обновления, резервирования, удаления, iPhone и desktop. Не добавлять восстановление через слабый PIN.
- Секреты синхронизации: отдельная проверка жизненного цикла, потеря ключа, отзыв, повторное подключение. Не передавать ключи в логи или публичную проекцию. Не изменять production Worker до проверки.
- Перед обработкой реальных данных несовершеннолетних проверить правовое основание и эксплуатационную защиту. Только синтетические данные в CI.

## Реализован отдельный прототип шифрованного хранилища

`tools/prototypes/local-vault.mjs` работает только с БД `teachapp-vault-lab-*`. PBKDF2-SHA256 (600 000 итераций), AES-256-GCM, независимая соль, случайные 96-битные IV с проверкой повторов на один снимок, непереносимые между слотами/областями конверты (AAD), непрозрачные ID, зашифрованный манифест. Криптография выполняется до атомарной транзакции; открытие заново проверяет полноту, лишние/пропущенные/подменённые записи. Пароль и ключ не сохраняются. Видны область, количество записей и размеры шифротекста. Это только LAB с синтетическими данными: нет подключения к живой базе, фоновой записи, изменения схемы, удаления источника, индексов и полноценного восстановления/ротации. Не является шифрованием действующей базы или готовой миграцией. Нужны независимый review криптографического протокола, интеграция, измерения памяти/времени, проверка квоты и физическая приёмка.

### Следующая контрольная точка LAB

CAS полной зашифрованной ревизии (сравнение всех ранее аутентифицированных байтов внутри транзакции), новый salt/ID/IV при изменении, смена пароля и отдельный переносимый ciphertext-only файл восстановления. Восстановление допускается только в пустую LAB-базу, с проверкой всех записей до записи; создаётся новая независимая ревизия. Проверяются конкурентная запись, устаревшая ревизия, старый пароль, повреждённая копия и запрет перезаписи. Это ещё не полноценный доступ к записям по индексам; полный снимок дорог по памяти и CPU. Не защищает от полного отката всей базы атакующим с доступом к профилю браузера. Не подключать к рабочим данным до независимой проверки и плана миграции.

### Полная схема в синтетическом контуре

`vault-schema-adapter.mjs` принимает только полную переносимую копию текущего формата после штатной проверки связей. Реализован тестовый Promise-интерфейс таблиц/составных индексов, уникальных ключей, readonly и атомарного CAS записи, с отказом при конфликте без повторного исполнения callback. Тестируются реальный снимок школьного журнала и тренерского состава, независимое восстановление и отсутствие изменений исходника. Для этой репетиции один отдельный scope `workspace`, без разделения ключей school/coach и без сохранения контрольных точек sync. Полный снимок перечитывается и перешифровывается при каждой записи; это измеримый baseline, не production DB. Нет raw IDB/cursor API, полноценной семантики всех запросов, переключателя и очистки исходника. Запрещены потери JSON-типов, отказ при неподдерживаемых значениях. Реальные данные не загружать в LAB.


### Репетиция обратимой миграции IndexedDB (LAB)

`vault-migration-rehearsal.mjs` создаёт отдельные native IndexedDB с полной текущей схемой и индексами, только с префиксами `teachapp-plain-lab-source-` и `teachapp-plain-lab-rollback-`. Исходник читается атомарным снимком всех таблиц; зашифрованный снимок открывается повторно и сравнивается с исходником до/после. Изменение исходника или зашифрованного снимка блокирует подтверждение переноса. Обратное восстановление читает и аутентифицирует vault, проверяет связи, пишет все таблицы одной транзакцией только в отдельную пустую rollback-базу и сверяет результат. Оригинал и vault не удаляются; неподходящие имена баз и перезапись запрещены. В rollback-базе данные открытые, поэтому использовать только синтетические записи.

Это не атомарное переключение между БД: сравнение фиксирует наблюдаемое состояние, не удерживает блокировку от следующей записи. Нет переключателя активной базы, барьера для всех вкладок, защиты от полного отката, разделения ключей school/coach, теста квоты или физической приёмки. До реализации этих условий нельзя подключать модуль к действующему приложению. Проверка: `node --test tests/vault-migration-rehearsal.test.mjs`; полный CI обязателен.


### LAB: согласованный маршрут хранилища

`vault-router-lab.mjs` вводит отдельный долговечный указатель фазы source → vault → rollback, фиксированные имена БД для ID репетиции и обязательный эксклюзивный Web Lock для каждой операции. Перед переключением повторно сверяется источник; ожидающие записи после переключения читают новый маршрут. Пароль передаётся только для операции; при отсутствии/повреждении указателя, неверном пароле или отсутствии Web Locks нет автоматического перехода на открытые данные. Восстановление выполняется в отдельную пустую rollback-базу перед обновлением указателя. При сбое указатель остаётся прежним; незавершённый staging/rollback может потребовать отдельной диагностики и нового LAB ID. Тесты используют синтетическую очередь блокировок; реальный межвкладочный Web Locks и прерывание браузера ещё не проверены.

Это кооперативный барьер только для клиентов, использующих этот LAB-модуль: прямые записи в IndexedDB обходят его. Не подключён к UI, sync или действующей базе; не защищает от отката/подмены всего профиля. Разделение ключей, полноценный интерфейс транзакций, физические тесты и производственное переключение остаются открытыми.


### LAB: повтор после прерывания и симулированной нехватки места

`stage({password,resume:true})` повторно подтверждает ранее записанный vault только при полном совпадении с актуальным источником. `rollback({password,resume:true})` разрешает завершить переключение, если уже записанная rollback-база целиком совпадает с аутентифицированным актуальным vault. Сравнение существующей rollback-базы и запрет перезаписи выполняются внутри одной native readwrite-транзакции. Без явного resume непустой адрес назначения отклоняется. Изменённая база, неправильный пароль и несовпадение снимка не допускают переключения; активным остаётся vault. Повторный запуск при несовпадении требует отдельной диагностики.

Тесты инъецируют QuotaExceededError в середине записи rollback и при сохранении указателя фазы; проверяют атомарный отказ, точный повтор, отказ от устаревшего снимка и сохранность актуальной записи. Это симуляция ошибок API, не измерение фактической квоты устройства или аварийного завершения iOS. Production не затронут.


### Маршрутизируемые транзакции нескольких таблиц LAB

Маршрутизатор предоставляет общий Promise-интерфейс transaction для source/vault/rollback под одним Web Lock. Callback вызывается ровно один раз, после завершения ссылки на store недействительны. В plaintext-фазах проверенный снимок фиксируется через native CAS всей базы и атомарную замену выбранных таблиц; raw конкурентное изменение вызывает отказ. В encrypted-фазе сохранён прежний зашифрованный CAS. Необязательное expectedGeneration блокирует устаревшее действие после переключения, до запуска callback. Тесты проверяют чтение, совместную запись, исключение callback, неверный пароль, устаревший маршрут и raw конкурентную запись. Это полно-снимочный синтетический baseline, не подключение действующей базы и не оптимизированная запись; plaintext-пути существующего LAB put пока оставлены без изменений. Production не затронут.


### LAB: независимая копия перед строгим переключением

`prepareActivationBackup` под Web Lock сверяет staged vault с источником, формирует отдельный зашифрованный файл с независимым паролем, точным ID маршрута, поколением и версией схемы, повторно открывает его. `openRouterActivationBackupLab` позволяет проверить файл офлайн без обращения к БД. Для `activateWithBackup` оператор должен сохранить файл отдельно, прочитать его обратно, указать ожидаемое поколение и saved=true. Под тем же кооперативным барьером сравниваются три снимка (копия, vault, источник). Ошибка пароля, повреждение, другой ID/формат или устаревшее содержимое не меняют маршрут. Флаг saved — заявление оператора, не доказательство записи на внешний носитель. Старый activate остаётся для прежних синтетических сценариев; это дополнительный строгий маршрут репетиции, не production-переключатель, не удаляет исходник и не подключается к действующей БД.

### Предварительная проверка действующей базы (только чтение)

В настройках → данные и безопасность → диагностика базы доступна проверка условий переноса. Один атомарный снимок, исключение device sync checkpoints из portable-части, предупреждение об их наличии и блокер незавершённой Delta-миграции. Проверяются связи, JSON-совместимость, лимиты текущего LAB, Web Crypto/Web Locks и приблизительная квота. Показаны только агрегаты и фиксированные коды замечаний; никаких файлов, ключей, записей, сети или запуска LAB. Это предварительное измерение, не гарантия квоты/памяти, не копия и не разрешение на переключение. Проверка не сохраняет результат.

### LAB: отдельная копия актуальной ревизии перед строгим откатом

`prepareRollbackBackup` создаёт отдельный зашифрованный файл поколения 2 с аутентифицированной ревизией vault, повторно открывает его и сверяет снимок. `rollbackWithBackup` требует saved=true, отдельный пароль, точное поколение, ревизию и содержимое. Перед записью и после неё сверяется актуальный vault, затем rollback-база; прежний исходник не перезаписывается. Даже повторная запись без изменения содержимого делает прежнюю копию устаревшей. После отказа указателя resume допустим только для того же проверенного снимка. Синтетический тест включает неправильный пароль, чужой ID, устаревшую ревизию, пустую rollback-базу до записи и отказ указателя. Это кооперативный LAB (raw writers обходят Web Locks), не production-переход, не физическое доказательство сохранности копии.

### Ограничение чтения для диагностики миграции

Перед загрузкой действующей базы диагностика считает строки всех таблиц в той же native readonly-транзакции. Если общий объём записей выше 10 000 (включая локальные checkpoint), возвращаются только счётчик и блокер без getAll. При допустимом количестве проверяется тот же атомарный снимок. Интерфейс не заявляет проверку связей, объёма или checkpoint, если снимок не загружен. Лимит консервативный и не гарантирует допустимое потребление памяти: одна запись может быть крупной. Обычные резервные копии и рабочие операции не меняются. Тест fake-indexeddb проверяет отсутствие getAll при превышении и точную границу. Это не подключение шифрования.

### Совместимость запросов LAB с native IndexedDB

Адаптер валидирует ключ и диапазон до просмотра строк (даже пустая таблица не скрывает ошибку DataError), для get требуется ключ/диапазон, getAll/count индекса допускают отсутствующий фильтр. get по диапазону возвращает первую запись в порядке первичного ключа. Регрессия сравнивает синтетическую native IDB и полно-снимочный адаптер на одних запросах. Не меняет рабочую базу и не объявляет полной совместимости raw IDB или production-маршрутизации.

LAB поддерживает сигнатуру getAll(query, count), но не новый overload getAll(options); в native реализации объект может трактоваться как словарь параметров, поэтому сравнение ошибок использует однозначно недопустимые ключи (boolean, NaN), а не options.

Сравнение с fake-indexeddb ограничено допустимыми запросами и обязательными ключами get; для необязательных фильтров отдельно проверяется строгий контракт LAB, поскольку преобразование аргументов и dictionary overload эмулятора отличаются. Это не утверждение о полной эквивалентности всех ошибочных native-вызовов.

### Атомарность при перехваченной ошибке запроса LAB

В writable полно-снимочной транзакции первая ошибка store/index-запроса блокирует CAS-коммит даже при перехвате ошибки в callback или пропуске await. Возвращаемый Promise по-прежнему отклоняется, но наблюдение за ним исключает необработанную ошибку для проигнорированного запроса. Проверка сравнивает аутентифицированную ревизию и содержимое до/после неудачных операций, затем подтверждает обычную успешную запись. Политика сознательно строже native IndexedDB для синхронных ошибок аргументов; readonly и основная БД не изменены. Никакой production-маршрутизации.

WebKit smoke дополнительно проверяет перехваченную и проигнорированную ConstraintError в multi-store LAB-транзакции на настоящих IndexedDB и Web Crypto. Сравнивается исходная ревизия и весь снимок, затем проверяется успешная атомарная запись двух таблиц. Это синтетический профиль, не физическая приёмка и не включение шифрования рабочей БД.

### LAB: барьер явно версионированных старых клиентов

В отдельной синтетической IndexedDB `teachapp-vault-fence-lab-*` репетируется native upgrade v10 → v11. В versionchange-транзакции сверяются все таблицы с переданным ранее проверенным снимком, затем атомарно создаётся маркер; устаревший снимок и отсутствующий исходник отклоняются. Кооперативные старые соединения закрываются, повторное открытие с явной v10 получает VersionError. При blocked поздняя миграция отменяется. Тесты проверяют гонку, отказ и сохранность источника; WebKit проверяет native закрытие и повторное открытие. Это не шифрование, не маршрутизация рабочей БД, не удаление plaintext и не защита от raw versionless IndexedDB или отката профиля. Никаких реальных данных. Production barrier остаётся отдельным условием.

### Общий контракт доступа к данным и привязка к поколению (LAB)

Публичные Promise-операции `js/db.js` используют единую фабрику `createDataAccess`; рабочий singleton по-прежнему неизменно привязан к native IndexedDB. LAB-обёртка `routedDataAccessLab` использует те же функции чтения, записи, индексов, транзакций и переносимого снимка, но закреплена за явным поколением маршрута. После переключения старый интерфейс отклоняется вместо неявного чтения или записи в другую фазу. Тесты проходят через реальные списки школьных хранилищ и проверяют атомарность, восстановление, отсутствие изменений native БД и отказ при неверном пароле. WebKit проверяет контракт при наличии Web Locks. `open()` и ограниченная диагностика `readBoundedSnapshot` остаются native-only; LAB всё ещё дешифрует полный снимок. Закрытие интерфейса предотвращает новые и ещё не начатые callback, но не отменяет уже запущенную запись. Пароль не сохраняется, однако остаётся строкой в активной closure. Не production-переключение и не готовое управление ключами.

### LAB: жизненный цикл записываемого интерфейса vault

`routedVaultLifecycleLab` выдаёт новый интерфейс только после полной аутентификации зашифрованного поколения 2. Нет plaintext fallback; старые интерфейсы и pending unlock инвалидируются при повторном входе. Idle timeout, hidden, freeze, pagehide, явная и межвкладочная блокировка закрывают интерфейс, очищают ссылку на пароль. Проверка действует перед callback, на store handles, после callback, перед криптографической подготовкой и внутри native CAS до мутации; завершённый коммит необратим, поэтому блокировка после постановки IDB-запросов не гарантирует отмены записи, а результаты закрытого сеанса не возвращаются. Любая ошибка операции закрывает текущий интерфейс. Уже полученные записи и работающие криптооперации не отзываются; строковый пароль и transient-копии не имеют гарантии стирания. Это writable LAB поверх полно-снимочного формата v1, не неизвлекаемый writable ключ, не production lifecycle/UI/cache purge, не активация рабочей базы. Тесты: ошибочный пароль, expiry, remote lock, гонка авторизации, callback/CAS, смена поколения; WebKit на реальной IndexedDB.

### LAB: записываемый сеанс без удержания строки пароля

`openVaultWritableKeySessionLab` импортирует пароль один раз в неизвлекаемый PBKDF2 CryptoKey с единственным разрешением deriveKey. Сеанс хранит только ссылку на этот эквивалент пароля; каждый новый снимок по-прежнему получает новую соль, случайный vaultId и IV, AES-GCM ключ выводится заново. Формат v1 не изменён: обычное открытие паролем, экспорт и независимое восстановление совместимы. Сеанс не выдаёт ключ вызывающему коду, привязан к имени базы и области; закрытие, ошибка или конфликт отбрасывают ссылку. Старые записываемые интерфейсы не возобновляются. Проверяется отсутствие повторного импорта, невозможность экспорта материала, свежая соль, совместимость восстановления, конфликт и чужая база. Временные строки при вводе и ожидающей авторизации, работающие операции WebCrypto и уже выданные данные нельзя гарантированно стереть. Материал остаётся эквивалентом пароля и не защищает от выполняемого внутри origin вредоносного JS. Нет независимого криптоаудита, производственной активации или физической приёмки.

### LAB: записываемый экран журнала

Отдельная страница `tools/prototypes/vault-ui/writable.html` доступна только на localhost и создаёт строго фиксированный синтетический класс, ученика, урок, оценку и ревизию. UI получает зашифрованный интерфейс только после аутентификации поколения 2; запись оценки и ревизии атомарна, устаревший UI отказывается перезаписывать изменённую оценку. Блокировка очищает пароль, оценку, ссылку на сеанс и ревизию в UI; после reload нужен новый вход. WebKit проверяет сохранение, внешний конфликт, очистку и mobile layout. Нет импорта реальных данных, произвольных паролей, production route, удаления исходного plaintext или активации рабочего приложения; страница не включена в статический release allowlist.

### LAB: общая производственная команда журнала

`js/journal-commands.js` содержит существующую атомарную команду вставки/замены оценок с проверкой ученика, урока, ограничений нагрузки, участия, освобождений и истории. `store.js` оставляет native backend и обновляет только собственный кэш; localhost LAB использует ту же команду через защищённый интерфейс, без подключения к глобальному состоянию. Опциональная привязка к последнему событию истории блокирует повторную запись даже после ABA-изменения оценки (в LAB применяется всегда). Модуль включён в precache, UI LAB исключён из production пакета. Сценарии проверяют идентичный результат native и vault, сохранение веса, историю, устаревший урок, особые отметки и независимость баз. Не полный перенос всех экранов и кэшей, не активация production.

### LAB: отдельный экземпляр школьного состояния

`createSchoolSession(access)` использует тот же набор школьных операций, что и обычный store, но фиксирует собственный backend и собственное состояние/подписки. Полные backup/restore и произвольный доступ к хранилищам не выдаются этим интерфейсом. Асинхронные команды и undo сериализованы, ошибка команды закрывает экземпляр; close отцепляет кэш, сбрасывает ранее выданный объект состояния, подписки и закрывает переданный access. Открытые копии отдельных объектов, ранее отданные результаты и уже завершённые записи отозвать нельзя; UI обязан очистить DOM и привязать close к lifecycle. Сессионный API не является отдельной криптографической границей для workRecords/meta, которые используют общую workspace LAB базу. Рабочий singleton остаётся native; демо-журнал использует отдельный экземпляр store и закрывает его вместе с экраном. Тесты проверяют классы, учеников, уроки, отметки, историю, независимость native и второго экземпляра, отмену старых undo и гонку queued/pending при блокировке. Нет production активации, переключателя глобального backend, полного UI-переноса или физической приёмки.

### LAB: тренерские команды и отзыв снимка

`createCoachSession(access)` использует те же команды и проверки, что и native `coach.js`, но фиксирует явный backend и ограничивает операции семью `coach*` хранилищами. Команды сериализованы, аргументы копируются перед очередью, ошибки закрывают экземпляр. `loadCoachForView` удерживает только текущий выбранный снимок; новая загрузка, успешная запись и close переключают прежний объект-проекцию на пустые данные. Close аннулирует ожидающие результаты и queued команды. Уже выданные строки/копии, `loadCoach` и аналитические результаты не гарантированно стираются: UI обязан убрать их из DOM и собственных кэшей. Сеанс не выдаёт raw DB, школьные таблицы или общий workRecords; это ограничение API, не криптографическое разделение workspace vault. Native API сохранён. Тесты проверяют команды, игроков, тренировочную нагрузку, матч, LIVE-ревизию, уникальность номера, независимость native и WebKit lifecycle. Полная интеграция тренерских экранов и смежных модулей, production migration и физическая приёмка не выполнены.

### LAB: рабочие записи и область доступа

`workRecordScope` единообразно классифицирует `workRecords` для трёхключевой репетиции и `createWorkSession(access,scope)`. Область workspace — не wildcard. Выборки фильтруются по области; запись проверяет и новый, и прежний объект внутри транзакции (запрещён перенос плана между областями через замену ID). Подключены существующие команды конспектов, календаря, нормативных назначений, видеоразбора, станции, материалов, тактики, целей и инвентаря. Native обёртки сохранены, новый модуль входит в precache. Ограниченный API не выдаёт raw workRecords, полные архивы или их каскадное удаление; document presets в localStorage, применение материалов и остальные специальные команды пока отдельно. Закрытие блокирует выдачу ожидающего результата и queued команды; ранее выданные записи требуют очистки UI. Это row-level API над общей workspace LAB базой, не отдельное криптографическое разделение; три ключа и writable multi-scope ещё не объединены. Тесты проверяют запрет смены области/удаления, совместимость классификации, сохранность native, WebKit lifecycle. Production cutover не выполнен.

### LAB: инструктажи и схемы зала

Школьный `createWorkSession` теперь использует общие с native функции записи инструктажа и схемы зала. Инструктаж требует явного подтверждения, фактических участников существующего класса и допустимой даты; схема не может заменить запись иного вида. Coach/workspace не получают этих команд или их записей. Сохраняется сериализация, закрытие при ошибке и независимость native DB. Регрессия проверяет зашифрованный LAB, обновление схемы, запрет подмены, неверных участников, неподтверждённого инструктажа и записи после закрытия. Production, интеграция UI и отдельные криптографические области пока не активированы.

### LAB: индивидуальные цели и применение материалов

Школьный сеанс поддерживает запись индивидуальных целей ученика по lineageId, сохраняя проверку существующего ученика и неизменность владельца. Применение переносимых КТП и тактических шаблонов использует общий с native код, фиксированный backend и явную область: school создаёт независимый КТП и темы атомарно, coach создаёт новую схему существующей команды, workspace не выдаёт команду. Применение реквизитов документов в localStorage по-прежнему только native; в LAB отклоняется до обращения к нему. Проверены подтверждение, запрет чужой области/ученика, смены владельца, неизвестной команды, запись после закрытия и сохранность native. Нет production cutover, полной интеграции интерфейсов или криптографического разделения областей.

### LAB: специализированные школьные и тренерские команды

Через фиксированный backend школьного сеанса доступны олимпиада и переход этапа, портфолио, пересдачи и альтернативные задания, включая чтение по уроку. Сохранены проверки фактических участников, связанности этапов, ревизий, учебного года, ограничений нагрузки и явного подтверждения. Coach поддерживает сезонные планы (удаление только с исходной ревизией в ограниченном API) и регламенты матчей с проверкой уникальности. Native обёртки продолжают использовать прежнюю базу. Тесты проверяют разделение областей, устаревшие ревизии, дубликаты, неверные ссылки, отзыв и независимость native. Нет production cutover, полного переноса UI или отдельной криптографической границы.

### LAB: оставшиеся рабочие команды

Подключены история КТП (снимок, список, восстановление независимой копией, подтверждённое удаление), турнирные сетки и результаты (CAS, групповые места), достижения школьного и тренерского контуров. Достижения проверяют область старой и новой записи; ограниченный сеанс не читает смешанный архив, создание записей для архивных субъектов остаётся native. Подтверждение удаления версии КТП нельзя обойти общим удалением в LAB. Native API и формат хранения не изменены. Тесты проверяют области, создание копии, CAS, подтверждения, запрет переноса достижения между областями и сохранность native. Production и криптографическое разделение writable областей остаются отдельными условиями.

### LAB: три записываемые области и атомарная фиксация

В отдельной репетиции `vault-partitioned-lab.mjs` три шифрованные области и registry находятся в отдельных object stores новой IndexedDB. Активация всех трёх ciphertext и указателя атомарна; запись одной области фиксирует её ciphertext и ревизию в одной транзакции с CAS, не затирая ревизии остальных. Сеанс получает только свой пароль и неизвлекаемый ключевой материал, ограничен таблицами/классификацией, отзывается при ошибке, close и тайм-ауте. Реальные школьные рабочие и тренерские команды проверены в синтетическом контуре. См. [ограничения и проверку](SECURITY_SCOPES_LAB.md). Этот LAB не активирует production, не обеспечивает сквозных транзакций, работу исторических связей без owner archive, полный школьный store с настройками, экспорт/ротацию всего набора, физическую приёмку или независимый аудит. ### LAB: проверяемая копия и атомарная ротация разделённых ключей

Новый разделённый LAB поддерживает независимый ciphertext-only файл с отдельными паролями копии, аутентифицированными исходными ревизиями, полным повторным открытием и восстановлением только в новый пустой набор. Ротация всех трёх областей требует точного сохранённого файла, сравнивает данные и исходные ревизии, затем атомарно обновляет все ciphertext и указатель. Сбой или устаревшая копия не изменяют активный набор; старые пароли и ревизии отклоняются. См. [SECURITY_SCOPES_LAB.md](SECURITY_SCOPES_LAB.md). Это не production перенос: остаются разделение school/owner meta, исторические ссылки, общий UI и миграция рабочего источника, независимый аудит и физическая приёмка.

### LAB: школьные настройки и исторические ссылки

В явном school-v2 layout текущий школьный store (включая журнал и правила оценивания) работает со своим ключом. Пять школьных полей settings отделены от всех остальных owner-настроек; неизвестные поля сохраняются в owner. Архивная история оценок остаётся с архивом, а текущая — с действующими школьными таблицами. Полное объединение восстанавливает поля и проверяет классификацию/связи. v1 LAB не изменяется; перенос в school-v2 только в отдельный набор. Межобластной перевод года, полный UI и production cutover всё ещё не реализованы. См. [SECURITY_SCOPES_LAB.md](SECURITY_SCOPES_LAB.md).

### LAB: межобластной перевод учебного года

В school-v2 реализован перевод года с подтверждением и тремя ключами владельца: preview по ревизиям, независимая проверенная копия, общая native подготовка, атомарный CAS school+workspace с сохранением тренерской ревизии, перенос истории к архиву, проверка полного снимка и восстановление прежнего состояния в отдельном наборе. ### LAB: экран переноса и раздельные записываемые сеансы

На localhost доступен `tools/prototypes/vault-ui/partitioned.html`. Только фиксированный синтетический источник и публичные демо-пароли. Пользователь скачивает независимую копию, выбирает сохранённый файл и подтверждает перенос; неправильная копия не активирует набор. Затем отдельные school, coach, workspace сеансы выполняют настоящие команды школьного журнала, команды тренера и календаря. Lifecycle закрывает соответствующую область при ручной блокировке, все при hidden/freeze/pagehide/idle и сообщении lock-all этого layout/ID через BroadcastChannel. Очистка UI и кеша, отказ устаревших операций и защита перед native CAS; уже начавшуюся атомарную запись нельзя гарантированно отозвать. Тестируются реальный WebKit, выбранный файл, неверная копия, запись, независимая блокировка, reload и межвкладочный отзыв. См. [атомарный перенос LAB](SECURITY_PARTITION_MIGRATION_LAB.md). Нет production маршрута и не принимаются рабочие копии/пароли. Физическая приёмка, подключение всех production экранов/sync и независимый аудит не выполнены.

### RC3: единая проверка разбиения и native-схемы

Чистый `js/vault-layout.js` используется одинаково из native диагностики и LAB. Проверка обратной сборки сравнивает записи по ID и все JSON-значения, не меняя исходник. `readBoundedSnapshot` сверяет версию, имена, keyPath, autoIncrement и полный набор индексов (включая unique/multiEntry) в той же readonly-транзакции до чтения. Несовпадение, контрольные точки sync без стратегии переноса или неудачная обратная сборка блокируют готовность. Отчёт только агрегированный, `activationAllowed` всегда false; не активирует шифрование, не меняет v10 и не заменяет независимую копию/приёмку. Полный production UI/sync cutover и сохранение контрольных точек остаются открытыми.

### RC3: контрольные точки устройства в отдельном LAB layout

Добавлен явно выбираемый school-v3-device-migrated (отдельное имя синтетической БД), который атомарно переносит обычные school/coach checkpoint и связанные status в ciphertext workspace.deviceMeta. Обычный scope API не получает эту таблицу; запись владельца сохраняет её неизменной, ротация всех ключей и отдельная локальная копия формата 2 сохраняют полный снимок. Формат 1 по-прежнему запрещает контрольные точки; явный локальный формат 2 несовместим с переносимой копией и не используется для облачного/межустройственного импорта. Неизвестные записи, повреждённые/несогласованные метаданные и Delta binding блокируют переход. Проверка структуры вложенного конверта не заменяет его аутентификацию sync-паролем. Рабочая синхронизация, перевод года в новом layout и production UI остаются отключёнными. Native диагностика учитывает размер всех записей и не разрешает активацию.

### RC3: атомарный синтетический обмен после переноса

`createSyncExecutor(access)` фиксирует явный backend и переиспользует существующий протокол с CAS, проверкой checkpoint, конфликтов и неопределённой записи. Обычный `executeSync` по-прежнему навсегда привязан к native db. В device-local LAB владелец с тремя ключами запускает только явный синтетический обмен; единый снимок всех областей проверяется до записи и сравнивается внутри одной native транзакции. Изменённые ciphertext и registry коммитятся вместе; неизменённая область не перешифровывается. Checkpoint/status записываются в deviceMeta и недоступны обычному scope API. Тесты: повтор без PUT, изменение, сохранение другой области и гонка после принятого сервером PUT без затирания локальной записи/ревизии. Это тестовый backend, не подключение персонального auto-sync/production или физическая приёмка.

### RC3: репетиция штатного приложения с фиксированным owner backend

`openOwnerAppRehearsal` требует явного synthetic=true и все три независимых ключа, использует полную транзакционную модель device-local LAB и запрещает изменение/удаление checkpoint через общий UI. Только специальный sync executor может изменять checkpoint. `tools/vault-app-smoke.mjs` подменяет модуль доступа к данным исключительно в отдельном WebKit контексте localhost, блокирует внешнюю сеть и Service Worker, проверяет настоящий экран журнала, запись оценки и истории, команду тренера, reload, обычную резервную копию без checkpoint, запрет raw DB, отсутствие native teachapp и закрытие доступа. Это all-key owner-репетиция, не production routing и не доказательство очистки всех уже выданных копий/DOM после блокировки. Production статический пакет не содержит LAB, паролей или маршрута подмены. Отдельно нужны интеграция bootstrap/login, lifecycle и production sync, приёмка физических устройств и независимый аудит.

### RC3: bootstrap и жизненный цикл владельца

Вынесен одноразовый `createOwnerSessionLifecycle`: явный unlock, отсечение устаревших результатов, monotonic idle, hidden/freeze/pagehide, BroadcastChannel с ограничением по имени набора, terminal lock (повторный вход только в новом документе). Полный owner LAB держит только закрываемые неэкспортируемые WebCrypto handles, а не три строки паролей; значения формы очищаются до ожидания входа. WebKit репетиция использует отдельный login, не загружает реальные экраны до успешной аутентификации и очищает документ с reload при lock. Native v10 при VersionError или реальном versionchange на новую версию/удаление необратимо отказывается повторно открывать источник в этом документе; при смене версии активный UI отзывает school cache и перезагружается. Запрещена автоматическая активация production v11. Не гарантируется очистка произвольных JS ссылок, завершённых транзакций и физического накопителя. Реальные ключи, production migration/route и независимая приёмка остаются открыты.
