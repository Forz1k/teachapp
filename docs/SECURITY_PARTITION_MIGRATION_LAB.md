# Security 6.1 — атомарный перенос трёх областей (LAB)

Только отдельная синтетическая база `teachapp-partition-migration-lab-*`. Не подключать рабочие данные. Этот модуль не является разрешением на миграцию production.

1. Старый источник имеет полную текущую схему native IndexedDB и явную версию 10. `preparePartitionLegacyMigrationLab` читает все таблицы одной транзакцией, проверяет строгое JSON-представление, связи и классификацию school-v2. Создаёт независимый зашифрованный файл с тремя паролями и аутентифицированной идентичностью исходника/ревизий. Открывает файл повторно и сверяет снимок.
2. `migratePartitionLegacyLab` требует три новых пароля, три независимых пароля копии, явные saved=true и confirmed=true, повторное открытие файла. Сверяет идентичность исходника и все данные, создаёт и проверяет три ciphertext-снимка до открытия upgrade-транзакции.
3. В native versionchange v10 → v11 повторно читает все исходные таблицы и сравнивает строгое каноническое содержимое. Только если совпадают, **в одной транзакции** удаляет синтетические plaintext object stores, создаёт три зашифрованных store и registry. Ошибка quota, изменение источника или blocked отменяют весь upgrade; старые таблицы и версия сохраняются. После успеха явное открытие v10 получает VersionError. Это удаление object stores, не гарантированное физическое стирание носителя.
4. Доступ через `partitionedVaultLab(id,{layout:'school-v2-migrated'})` допускается лишь к существующей v11. Не создаёт новый набор, не открывает legacy как fallback. Все ранее реализованные scope-сессии и операции применимы.
5. Откат: создать независимую копию **последнего** активного снимка; `restorePartitionLegacyCopyLab` с подтверждением восстанавливает данные только в отдельную пустую legacy-базу. Проверяются связи, полная запись одной транзакцией и повторное чтение. Не откатывает номер версии и не перезаписывает оригинал.

Тесты: `node --test tests/vault-partition-migration-lab.test.mjs`, полный CI, WebKit. Проверяются другая база/устаревшая копия, имитация квоты при записи registry, конкурентная исходная запись во время шифрования, старое соединение, защищённый журнал, восстановление актуального снимка и отказ от перезаписи.

Ограничения: только синтетические данные. Не гарантирует физическое стирание, защиту от полного отката профиля браузера или произвольного JS в origin. saved — подтверждение оператора, а не доказательство сохранения на внешнем носителе. Нельзя удалять рабочий plaintext до независимой приёмки, фактического сохранения и проверки резервной копии на другом устройстве, проверенного rollback-маршрута, ревизии UI/sync/всех прямых native-потребителей и физической проверки квоты/прерывания. Production-версия не меняется.

## RC3: явный device-local вариант

Для синтетической репетиции с локальными checkpoint используется только `deviceLocal:true`, `school-v3-device-migrated`, отдельный префикс `teachapp-partition-device-migration-lab-` и локальная recovery v2. Сохранение и восстановление копии требуют явного выбора этого режима. Checkpoint сохраняется непрозрачным вложенным конвертом в workspace.deviceMeta, не в portable meta. Сеансы school/coach и обычный owner API не читают/не меняют deviceMeta. Полный снимок доступен только с тремя паролями; независимая копия/ротация и откат в пустой синтетический источник сохраняют эти записи. Active Delta, незнакомые ключи и несогласованный status запрещены. Не использовать копию для переноса между устройствами. Это не интеграция действующей синхронизации и не разрешение на миграцию рабочих данных.

В device-local LAB доступны `prepareDeviceSync`, `executeDeviceSync`, `deviceSyncState`: только три пароля владельца, явный mock/локальный relay, никакого native fallback. Общая команда обмена использует CAS всего набора, сохраняет checkpoint вместе с данными и не меняет неизменённые разделы. Реальный сетевой сервис, фоновые задачи и рабочие UI не переключаются.

`tools/vault-app-smoke.mjs` проверяет реальный `index.html` и модульный граф приложения с временной подменой db.js в отдельном WebKit профиле. В опубликованном db.js нет переключателя. Owner API требует все три ключа, не позволяет менять checkpoint при обычной записи/восстановлении, запрещён raw open. Это автоматическая репетиция, не производственный логин/миграция.

RC3 owner-app rehearsal: вход тремя ключами до импорта app.js, неправильные ключи не открывают UI, ключевые handles вместо сохранённых строк, терминальный lock, очистка DOM и новый документ, межвкладочный отзыв. В рабочем пакете добавлен fail-closed native fence, но production маршрут не переключается.
