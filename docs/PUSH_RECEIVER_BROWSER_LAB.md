# Isolated browser push receiver

The localhost-only module worker under tools/prototypes/push-receiver/ is never registered by the main application. Synthetic consent is memory-only, disabled by default and lost on worker termination. Commands are accepted only from the exact fixture window, via a MessagePort. A real push listener delegates to the previously tested strict generic handler. Browser smoke creates this separate registration before the main worker, grants notification permission only in a temporary Chromium profile, tests denied/malformed signals through an isolated message rehearsal, dispatches a valid synthetic PushEvent through CDP ServiceWorker.deliverPushMessage and checks actual registration.getNotifications(). It then disables consent, closes notifications, unregisters, and resets permissions. No PushManager.subscribe, external provider, production worker, real account or physical device test. The browser can generate fallback notifications for real push events that do not show a notification; malformed/denied cases therefore use the explicitly synthetic message rehearsal.
