# Развёртывание собственного relay (TeachApp 4.0 beta)

Только для тестирования на синтетических данных до независимой проверки безопасности. Статический GitHub Pages не может запустить Node-сервер. Рабочий сервер и DNS не входят в эту поставку; используйте собственную согласованную инфраструктуру. Сервер не содержит клиентского пароля и не умеет расшифровать снимки.

## 1. Подготовка

Node.js 24, отдельный непривилегированный системный пользователь, приватный каталог вне репозитория и вне каталога сайта. Права каталога 0700, файлов 0600; доступ только у процесса relay. Не публикуйте секреты, реальные снимки, логи с Authorization или каталог хранения в GitHub.

Сгенерируйте отдельный случайный 256-битный токен на каждое устройство и контур:
    
    node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"

Создайте конфигурацию через защищённый механизм окружения вашего хоста (пример имён, не реальные ключи):

    TEACHAPP_SYNC_DIR=/private/teachapp-sync
    TEACHAPP_SYNC_ORIGIN=https://your-approved-pwa-origin.example
    TEACHAPP_SYNC_TOKENS={"school":["<token-device-A>","<token-device-B>"],"coach":["<other-token>"]}
    PORT=8787

Origin — только схема, хост и порт веб-приложения, без пути и завершающего слеша. Не используйте одни токены в обоих контурах. Для отключения контура задайте пустой массив. Передайте реальную конфигурацию как переменные окружения, не как аргументы командной строки.

Запустите:

    npm run sync:relay

Relay слушает только 127.0.0.1. Подключите HTTPS reverse proxy на согласованном домене к локальному порту. Разрешите только API /v1/snapshot/school и /v1/snapshot/coach с GET/PUT/OPTIONS, не журналируйте Authorization, запросы или ответы. Установите ограничение частоты, ограничение размера тела до 90 MiB, таймауты, мониторинг доступности без содержимого. Не допускайте доступ к каталогу данных через веб-сервер. Настройте резервные копии каталога, контроль доступа и процедуры восстановления. Не запускайте несколько экземпляров на одном каталоге; блокировочный файл защищает от этого. После аварии удаляйте .relay-lock только убедившись, что экземпляр остановлен. Утеря состояния relay приводит к блокировке синхронизации, а не автоматической перезаписи.

## 2. Первое подключение двух тестовых устройств

1. Обновите PWA до 4.0 и создайте защищённые копии обоих устройств.
2. На первом: Настройки → Резервная копия → Синхронизация устройств · бета. Выберите контур, адрес HTTPS, индивидуальный токен и длинный случайный пароль шифрования контура. Получите предпросмотр, подтвердите создание общей ревизии.
3. На втором устройстве используйте его отдельный токен и тот же пароль шифрования выбранного контура. Контур должен быть пустым или точно совпадать с сервером. При отличиях данные не перезаписываются.
4. Выполните сравнение и явную синхронизацию. Проверьте записи, внесите разные тестовые изменения на обоих устройствах и повторите.
5. Конфликты требуют ручного выбора. При ошибке сети или локальной записи повторите сравнение. Номер ревизии и результат показываются после атомарной локальной записи. Не открывайте другие окна TeachApp во время синхронизации.

## 3. Эксплуатационные ограничения

Пароль и токен необходимо вводить для каждой новой сессии синхронизации. Токен не является паролем шифрования. Для отзыва устройства удалите его токен из конфигурации и перезапустите relay; уже полученные устройством данные не удаляются. Ротация общего пароля и полноценная привязка индивидуальных криптографических ключей не реализованы. Не пытайтесь сбрасывать серверную ревизию или переиспользовать чужой каталог, чтобы обойти конфликт. До приёмки не включать реальные данные. См. [модель угроз и ограничения](SYNC_DESIGN.md).

## 4. Альтернативный тестовый хостинг

С 4.0.1 доступен Cloudflare Workers с SQLite Durable Objects. См. [инструкцию](CLOUDFLARE_SYNC.md). Только тестовые данные, ограничение пакета 1 MiB. Node relay выше по-прежнему поддерживается.
