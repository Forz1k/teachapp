# Облачный стенд TeachApp 4.0.1 — Cloudflare Workers

Только синтетические данные до согласования и независимого аудита. Не размещайте реальные данные учащихся на этом стенде. GitHub хранит исключительно код, Cloudflare — зашифрованные пакеты; шифрование не заменяет правовое основание и требования размещения данных.

## Что подготовлено

- Worker с HTTPS и SQLite-backed Durable Objects. Отдельный объект на школьный и тренерский контур, атомарный CAS, отсутствие публичного доступа к снимкам.
- Совместим с клиентом TeachApp 4.0, сохраняет текущий self-hosted Node relay. Новых runtime-зависимостей нет. Для CLI/CI используется Wrangler фиксированной версии.
- Ограничение тела запроса 1 MiB (полный JSON с зашифрованным пакетом), ниже лимита SQLite. При превышении сервер отвечает 413; локальная база не перезаписывается. Для больших снимков используйте согласованный собственный сервер; разбиение пакетов пока не реализовано.
- Секреты Worker: точный HTTPS origin приложения и SHA-256 хеши случайных токенов доступа. Токены, пароль шифрования, снимки и данные учащихся не должны попадать в GitHub.
- Бесплатный тариф имеет квоты на запросы, CPU и операции хранения; при превышении квоты операции могут остановиться. Не включайте платный тариф автоматически. Проверяйте актуальные условия https://developers.cloudflare.com/durable-objects/platform/pricing/ .

## Публикация (требуется однократная авторизация владельца)

GitHub Actions проверяет сборку и реальный локальный workerd без облачного аккаунта. Публикация по умолчанию отключена. Для включения необходимо иметь аккаунт Cloudflare, активировать workers.dev (либо собственный согласованный домен) и создать API token с минимальными правами на деплой Worker выбранного аккаунта. GitHub сам не выдаёт Cloudflare credentials.

1. В GitHub Settings → Secrets and variables → Actions создать secrets CLOUDFLARE_API_TOKEN и CLOUDFLARE_ACCOUNT_ID. Не отправлять их в чат и не коммитить.
2. Для каждого устройства и контура сгенерировать случайный 256-битный токен и его SHA-256. Команда ниже выводит оба значения локально; токен сохраняется у владельца в защищённом менеджере паролей. В GitHub secret записывать только хеш.
   
       node -e "const c=require('node:crypto');const t=c.randomBytes(32).toString('base64url');console.log('Device token:',t,'\nSHA-256:',c.createHash('sha256').update(t).digest('hex'))"

3. Создать secret TEACHAPP_SYNC_TOKEN_HASHES как JSON вида {"school":["<64-hex-hash-device-A>","<64-hex-hash-device-B>"],"coach":["<different-64-hex-hash>"]}. Пустой массив отключает контур. Одинаковые хеши в контурах запрещены. Ключи доступа не являются паролями шифрования.
4. В Actions variables задать TEACHAPP_SYNC_ORIGIN (точный HTTPS origin без пути и завершающего слеша; например origin GitHub Pages, если там опубликован именно ваш PWA). Затем установить TEACHAPP_CLOUDFLARE_DEPLOY=true. Эта переменная разрешает публикацию на main, не на PR.
5. Actions → TeachApp Cloudflare → Run workflow (main). После успешного деплоя взять точный HTTPS URL из шага Wrangler. GET /healthz должен вернуть {"status":"ready"}; это только проверка конфигурации, не проверка реальных данных.
6. На изолированных тестовых профилях PWA открыть Настройки → Резервная копия → Синхронизация устройств. Ввести URL, токен конкретного устройства и общий случайный пароль шифрования для этого контура. Создать первую синтетическую ревизию, подключить второе пустое устройство и сравнить записи. Не вводить настоящие данные учащихся.

При отзыве токена удалить его хеш из secret и повторно запустить workflow. Копии, которые уже были загружены на устройство, не удаляются. При отключении публикации снять переменную TEACHAPP_CLOUDFLARE_DEPLOY; это не выключает уже опубликованный Worker. Для выключения сервера отключите маршрут или Worker в Cloudflare и отзовите ключи.

## Локальная проверка

    npm ci
    npx --yes wrangler@4.161.0 deploy --dry-run
    node tools/cloudflare-smoke.mjs

Тест запускает локальный Workers runtime с временными синтетическими токенами и SQLite, проверяет отсутствие неавторизованного доступа, отдельные области, CORS, конфликт ревизий, шифрование и сохранение после перезапуска. Не требует Cloudflare API token и не публикует никаких данных.

Не считать успешную локальную проверку подтверждением облачного развёртывания. Проверка физического iPhone, живого HTTPS endpoint, правовых условий и независимый аудит остаются отдельными задачами.
