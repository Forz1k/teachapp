# TeachApp 5.2.0-rc.1 — приёмка кандидата

**Не развёрнуто.** Ветка PR #95. Исходная опубликованная версия 5.1.1, main `1bd6998027db193558b31350d4f6a54dd7414ed3`. Результаты проверок конкретного коммита смотреть в PR. Это кандидат статического PWA, не автоматический переход на новый облачный протокол.

## Автоматическая приёмка

- Полный npm test, validate, benchmark, Chromium, WebKit, реальная смена Service Worker с опубликованной 5.1.1. Сверка всех записей, старого зашифрованного checkpoint, незавершённого матча, сохранённого v2-профиля и отсутствия инициализации неподтверждённого контура.
- Независимое восстановление старой копии, офлайн-перезагрузка, повторный обмен без лишней записи.
- Cloudflare и Delta workerd: изоляция, большие снимки, ключи и ротация, гонки записи, перенос, локальный откат, подписанное возобновление источника, проверка повреждённой подписи, перезапуск обоих серверов.
- Обычные API не должны принимать LAB-маркер даже при совпадающем адресе; только явный проверенный LAB-адаптер. Отдельная рабочая область не блокируется.

## Перед статическим выпуском

Выпускать только после явного разрешения владельца, CI на точном финальном SHA и смены номера с rc на стабильный 5.2.0 с повторной CI. Не развёртывать Worker или Firebase вместе со статическим выпуском. Не использовать данные детей для тестов. Сохранить исходный коммит, текущие адреса и резервные копии каждого устройства.

## Рабочий Delta: отдельный допуск, пока запрещён

- Безопасный профиль: HTTPS endpoint, независимый токен устройства, хранение ключей и атомарная смена профиля и checkpoint. Текущий LAB endpoint намеренно loopback-only; нет переключателя production.
- Защита ключей: отдельные роли/секреты по контурам, операторский инвентарь, журнал доступа, ротация/отзыв, независимые резервные копии. Приватные signing JWK только в secret storage, не в git, браузере, логах или копиях данных.
- Долговременная гарантия seal: нельзя восстанавливать pre-seal БД назначения с прежней signing identity или запускать старый бинарник, не проверяющий барьер. При аварии остановить оба направления, сохранить проверенные архивы, согласовать ревизии и создать новую изолированную identity; не разблокировать источник по устаревшей квитанции.
- Перед переводом все устройства согласуют ревизии, сохраняют проверенные копии, прекращают запись. Подтверждение возврата всех устройств является операторской процедурой, а не автоматической серверной аттестацией. При новых данных назначения простой откат запрещён.
- Проверить физические устройства и независимую эксплуатационную/правовую приёмку; только затем отдельное разрешение на реальные данные и production deployment. Не передавать действующие ключи в экспериментальный контур.
